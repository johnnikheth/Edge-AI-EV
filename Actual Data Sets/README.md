# Actual Data Sets

Derived datasets for the Depot EV agents. Rebuild with `python3 -I "Actual Data Sets/build_data.py"` (stdlib only).
Raw files in `Raw Data Sets/` are never modified.

| File | Agent | Source | Real or synthetic |
|---|---|---|---|
| `battery_fade_by_chemistry.csv` / `.json` | Battery health | `ev_battery_health.csv` | Synthetic (CC0). Label as "simulated degradation model". |
| `arrival_profile_by_hour.csv` | Power (stress test) | `EVChargingStationUsage.csv` | Real, City of Palo Alto, 2016-2019 |
| `dwell_energy_quantiles.csv` | Power, Fleet planner (stress test) | same | Real |
| `palo_alto_session_sample.csv` | Power (stress test) | same | Real; 2,000 seeded sessions, no user or station columns |
| `build_report.json` | docs | both | Row counts and filters |
| `../reference-data.js` | all of the above | both | The tables above as one script the app loads (`REFDATA`). Regenerated by the build script. |

Limits:
- Battery fade is `fade% = rate x cycles` through the origin, per chemistry, with fast-charge and depth-of-discharge multipliers. The source has no real climate effect and unreliable remaining-useful-life values, so neither is used.
- Palo Alto sessions are commuter and public cars, not delivery vans. The app uses only the weekday arrival-time pattern (stress test). Dwell and energy tables are kept for reference but are not used: a van's departure and charge need come from its route.
- The `evening_arrival_long_dwell` group (arrive 16:00-20:59, stay over 6 h) is the closest match to an overnight depot.
